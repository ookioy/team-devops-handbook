# Чек-лист рецензування

Цей чек-лист використовується під час перевірки Pull Request для консольних утиліт.

## Порядок використання

Чек-лист проходиться рецензентом перед схваленням Pull Request.

Кожен пункт повинен мати однозначну відповідь «так» або «ні». Якщо хоча б одна обов'язкова перевірка не пройдена, рецензент залишає коментар із конкретним описом проблеми, а автор вносить виправлення окремим комітом.

Після виправлення автор відповідає на коментар, а рецензент повторно перевіряє зміну перед схваленням Pull Request.

## Функціональність

- [ ] Утиліта виконує заявлене призначення.
- [ ] Усі обов'язкові параметри командного рядка обробляються.
- [ ] Необов'язкові параметри мають коректні значення за замовчуванням.
- [ ] Некоректні аргументи обробляються без аварійного завершення програми.
- [ ] Для неправильного використання виводиться зрозуміле повідомлення про помилку.
- [ ] Команда довідки `--help` працює та описує доступні параметри.

## Коди завершення

- [ ] Успішне виконання завершується з кодом `0`.
- [ ] Помилки завершуються ненульовим кодом.
- [ ] Коди завершення відповідають опису в документації.

## Ввід і вивід

- [ ] Стандартний вивід `stdout` містить тільки очікуваний результат роботи.
- [ ] Повідомлення про помилки виводяться у `stderr`.
- [ ] Формат виводу відповідає документації та прикладам.

## Файли та конфігурація

- [ ] Утиліта коректно обробляє відсутні файли.
- [ ] Утиліта коректно обробляє неправильні або пошкоджені вхідні дані.
- [ ] Тимчасові та згенеровані файли не потрапляють у Git, якщо вони не потрібні.

## Документація

- [ ] README містить призначення утиліти.
- [ ] README містить вимоги для запуску.
- [ ] README містить приклад запуску.
- [ ] README описує параметри командного рядка.
- [ ] README містить приклад очікуваного виводу.
- [ ] README описує відомі обмеження утиліти.

## Перевірка змін

- [ ] Pull Request містить тільки зміни, пов'язані з поставленою задачею.
- [ ] У Pull Request немає випадково доданих секретів, логів або тимчасових файлів.
- [ ] Нові або змінені функції перевірені перед злиттям.
- [ ] Зміни не порушують уже наявну функціональність.
