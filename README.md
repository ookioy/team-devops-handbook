## Git hooks

У репозиторії використовується локальний `commit-msg` hook для перевірки формату повідомлень комітів.

Повідомлення коміту повинно мати формат:

```text
<type>: <description>
```

Дозволені типи:

- `feat` — нова функціональність;
- `fix` — виправлення помилки;
- `docs` — зміни документації;
- `refactor` — рефакторинг;
- `test` — зміни тестів;
- `chore` — технічні зміни.

Приклад правильного повідомлення:

```text
docs: update branching guide
```

Приклад неправильного повідомлення:

```text
wip
```

Тека `.git/hooks` не версіонується Git, тому після клонування репозиторію hook потрібно встановити вручну:

```bash
cp scripts/hooks/commit-msg .git/hooks/commit-msg
chmod +x .git/hooks/commit-msg
```

Після встановлення hook автоматично перевіряє повідомлення перед створенням кожного коміту. Hook діє тільки в поточному локальному клоні репозиторію.

Перед початком роботи після нового клонування репозиторію необхідно перевірити, що hook встановлений та має право на виконання.

Перевірити наявність встановленого hook можна командою:

```bash
ls -l .git/hooks/commit-msg

Якщо файл має право на виконання, у його правах доступу буде присутній прапорець `x`.
